# ТЗ: сценарий себестоимости, точка 0, дороги Европы, маржа и курсы НБУ

> **Статус: УСТАРЕВШИЙ (deprecated)** — не реализуется.  
> **Актуальная альтернатива:** [`freight-calculation-gemini-scenarios.md`](./freight-calculation-gemini-scenarios.md) — расчёт фрахта через ИИ Gemini и текстовые сценарии правил.

## Правила языка документа
- Основной язык: **RU** (термины API/кода: английский по принятому в проекте стилю).
- Связанные документы: `docs/specs/routes-server-workflow-and-freight-quoting.md`, `docs/specs/route-immutability-list-filters-deferred-country-breakdown.md`, `docs/specs/route-point-operations-rules.md`, `docs/specs/auth-authentication-authorization.md`, `docs/system.md`.

## 1. Цель
Дать **ADMIN** и **MANAGER** воспроизводимый инструмент расчёта себестоимости и формирования **окончательного коммерческого предложения (quote)** по заявке на фрахт с учётом:
- опциональной **точки 0** (подача транспорта до начала «боевого» маршрута заявки) — без её определения (или явного режима «без точки 0») не запускается расчёт пробега по странам;
- настраиваемого **сценария расчёта** (расходы, зарплата, суточные, дороги, маржа) — сценарии **хранятся только на сервере**; **ADMIN** и **MANAGER** могут **изменять параметры** сценариев и **выбирать сценарий** для расчёта по заявке; **выбор сценария обязателен** до расчёта пробега по странам;
- затрат в **валютах учёта затрат** и итогового предложения клиенту через **кросс-курсы НБУ** на дату расчёта.

## 2. Контекст и текущее состояние
- Уже есть: `Route`, `RouteRequest`, `FreightQuote`, admin API очереди заявок, роли `ADMIN` / `MANAGER` / `USER`.
- **Сценарии расчёта** (новая сущность): единственный источник правды — **БД на сервере**; **ADMIN** и **MANAGER** имеют одинаковые права на **чтение, создание, изменение и удаление** (или soft-delete) сценариев и на **выбор сценария** при расчёте по заявке (см. §8 RBAC).
- Создание draft quote / отправка клиенту: в существующем коде часть операций только `ADMIN` — в рамках общего workflow quote **уточнить продуктово** отправку; по сценариям требование зафиксировано: **MANAGER = ADMIN** для справочника сценариев.

## 3. Область работ (In scope)
1. **Точка 0 маршрута** (опционально): отдельная географическая точка «откуда выезжает порожний транспорт»; участок **0 → первая точка маршрута заявки** включается в полную длину рейса для расхода топлива (порожний режим), в суточные/дороги — по правилам сценария.
2. **Справочник сценариев расчёта** на сервере: именованные записи с полным набором параметров (§5), CRUD для ролей **ADMIN** и **MANAGER**; при расчёте по заявке пользователь **выбирает** существующий `scenarioId` (после выбора подтягиваются актуальные значения с сервера; в сохранённом расчёте/quote дублируется **снимок** параметров на момент расчёта — см. §7).
3. **Расчёт себестоимости** по формулам §5 с разбиением по статьям затрат и сохранением **снимка входных параметров** на дату расчёта (аудит).
4. **Дороги по странам Европы**: модель тарификации «за км» и/или «EUR за сутки» с фиксированным учётом **2 суток** для дневного тарифа (если выбран тип «в день»).
5. **Маржа**: либо **% от базы** (уточнение: от «чистого фрахта до маржи» / от себестоимости — зафиксировать в реализации как **% от суммы затрат до маржи**, если иное не согласовано), либо **фикс за рейс** в валюте; допускается комбинация «процент + минимум» во v2.
6. **Валюты**: все промежуточные статьи ведутся в заданных валютах затрат; **итоговая цена предложения** пересчитывается в валюту quote (например EUR/USD) через **официальные курсы НБУ** (кросс через гривну) на **дату расчёта**.
7. **Интеграция НБУ**: автоматическая подгрузка курсов на дату; кэширование на сервере; обработка недоступности API.

### 3.1 Порядок операций: пробег по странам
- **Создание пользовательской заявки** (`POST /api/v1/route-requests`) **не** запускает расчёт пробега по странам и **не** сохраняет `route_country_distances` / аналог; это зафиксировано в `docs/specs/route-immutability-list-filters-deferred-country-breakdown.md` §3.3.
- **Расчёт пробега по странам** (country breakdown, км по каждой стране на полилинии) выполняется **только после** одновременного выполнения условий:
  1. **Определена точка 0** — заданы координаты/адрес точки подачи **или** явно выбран режим «без точки 0» (эквивалент: старт расчёта с первой точки маршрута заявки).
  2. **Выбран сценарий расчёта** — в контексте запроса передан идентификатор `scenarioId` (сценарий должен существовать и быть доступен пользователю).
- До выполнения обоих условий UI не показывает финальный breakdown по странам (допустимы плейсхолдер/подсказка); backend **не считает и не сохраняет** `route_country_distances` / аналог для коммерческого контура заявки по этому шагу.
- При **изменении** точки 0 или сценария ранее рассчитанный пробег по странам считается **недействительным** до повторного запроса расчёта с новыми входными данными.
- Сценарий влияет на то, **какие** страны/участки попадают в тарификацию дорог (например, только EU из справочника); геометрия маршрута при этом строится по полному пути с учётом точки 0.

## 4. Вне области (Out of scope)
- Бухгалтерский учёт, НДС, акты, онлайн-оплата.
- Автоматический выбор «лучшего» маршрута между альтернативами.
- Прогноз курса на дату отгрузки (только дата расчёта).

## 5. Модель сценария (параметры)
Сценарий — **серверная** сущность (не localStorage и не только UI-пресеты). Каждая запись хранит служебные поля: уникальный `id`, человекочитаемое **`name`**, флаг **`isActive`** (неактивные не предлагать в выпадающем списке расчёта, но сохранять для истории), **`updatedAt`**, **`updatedByUserId`** (аудит).

Минимальный набор **числовых/бизнес-полей**:

| Параметр | Единица | Описание |
|----------|---------|----------|
| `fuelConsumptionEmptyLPer100km` | л/100 км | Расход **порожний** (дефолт из бизнес-требования: **35**). |
| `fuelConsumptionLoadedNonWinterLPer100km` | л/100 км | Расход **гружёный**, период **не зима** — **37** л/100 км (**зафиксировано**). |
| `fuelConsumptionLoadedWinterLPer100km` | л/100 км | Расход **гружёный**, **зима** — **40** л/100 км (**зафиксировано**). |
| `seasonMode` | enum | `WINTER` / `NON_WINTER` / `AUTO` (`AUTO` — зима/не зима по правилу календаря или дате начала рейса; иначе ручной выбор). Для расхода гружёного: при `WINTER` → поле зимы; при `NON_WINTER` → поле не зимы. |
| `fuelPricePerLiter` | UAH/л | Цена топлива. |
| `driverSalaryPercentOfFreight` | % | **17% от фрахта** — в ТЗ указано как доля от фрахта; это **циклическая** зависимость (зарплата от выручки). **Решение для v1:** считать от **базы до ЗП**: `freightBase = costBeforeDriverAndMargin`, затем `driver = freightBase * 0.17`, либо итеративно от предварительной «чистой ставки». **Нужно согласование с бизнесом**; в реализации заложить стратегию `DriverSalaryBasis` (enum). |
| `perDiemUsdPerDay` | USD/день | Суточные (**10 USD**/день по умолчанию). |
| `perDiemRouteDivisorKm` | км | Делитель длины для расчёта дней (**600** км = 1 условный день к формуле). |
| `perDiemFixedExtraDays` | дни | Добавка (**+2** дня). |
| `marginType` | enum | `PERCENT_OF_SUBTOTAL` / `FIXED_PER_TRIP`. |
| `marginPercent` | % | Если тип процент. |
| `marginFixedAmount` | сумма + валюта | Если фикс за рейс. |
| `proposalCurrency` | ISO 4217 | Валюта, в которой показываем клиенту (часто EUR). |

### 5.1 Формулы (v1)
- **Длины:**  
  - `L_empty_km` — сумма километров сегментов, где движение **порожнее** (точка 0 → первая точка груза + возможные холостые перемещения по правилам v1: минимум участок 0→start).  
  - `L_loaded_km` — километры **с грузом** (от первой точки погрузки до разгрузки по маршруту заявки).  
  - *Уточнение:* если несколько погрузок — v1: весь путь после первой погрузки считается гружёным, либо распределение по сегментам из UI; зафиксировать в UX.
- **Топливо:**  
  - `Fuel_empty = L_empty_km / 100 * fuelConsumptionEmpty`  
  - `fuelConsumptionLoaded(season)` — при расчётном сезоне **зима** (`WINTER` или ветка `AUTO`→зима): `fuelConsumptionLoadedWinterLPer100km` (**40**); при **не зима** (`NON_WINTER` или ветка `AUTO`→не зима): `fuelConsumptionLoadedNonWinterLPer100km` (**37**).  
  - `Fuel_loaded = L_loaded_km / 100 * fuelConsumptionLoaded(season)`  
  - `Fuel_cost_UAH = (Fuel_empty + Fuel_loaded) * fuelPricePerLiter`
- **Суточные (USD):**  
  - `days = floor(L_total_km / 600) + 2` (или `ceil` — **зафиксировать**; по смыслу «длина/600 + 2» обычно используют `ceil` для частичного дня; согласовать).  
  - `PerDiem_USD = days * 10`
- **Зарплата водителя:** от согласованной базы (см. циклическую зависимость выше), валюта — по настройке сценария (часто UAH или EUR).
- **Дороги (по странам EU):** только на основании пробега по странам, полученного по правилам **§3.1**; для каждой страны, через которую проходит маршрут (включая участок 0→start если применимо):  
  - либо `toll_eur_per_km * km_in_country`,  
  - либо `toll_eur_per_day * 2` (если тариф «в день» — **всегда 2 суток** для v1).  
  Справочник тарифов: отдельная сущность `CountryTollRule` + версионность или дата действия.
- **Себестоимость до маржи:** сумма всех статей в **единой внутренней валюте учёта** или с послинейным конвертом по курсам НБУ на дату расчёта.
- **Маржа:**  
  - при `%` — от согласованной базы (рекомендация: от **себестоимости до маржи**);  
  - при фиксе — добавить сумму в валюте.
- **Итог фрахта (до НДС):** `subtotal + margin`.

## 6. Курсы НБУ
- **Источник:** официальный API НБУ (курсы на **конкретную дату** `calculationDate`).
- **Правило кросса:** для пар `A/B` без прямого курса: `A_UAH` и `B_UAH` → `A/B = rate_A / rate_B` (как публикует НБУ: обычно гривна за единицу валюты).
- **Кэш:** не чаще 1 запроса к НБУ на дату для набора валют; TTL в пределах суток.
- **Сбой API:** блокировать «отправку quote» с понятной ошибкой; разрешить ручной ввод курсов **только ADMIN** (опционально v2) или повтор позже.

## 7. Данные и аудит
- Сущность **`FreightCalculationScenario`** (таблица на сервере): все поля из §5 + `name`, `isActive`, аудит последнего изменения. Изменение сценария **не пересчитывает** автоматически уже сохранённые quote; новые расчёты используют новые значения.
- Сущность **`FreightCostCalculation`** (или расширение `FreightQuote`):  
  - ссылка на `route_request_id`, `scenario_id`, `calculation_date`, `season_used`,  
  - **снимок параметров сценария** на момент расчёта (JSON или денормализованные поля), чтобы воспроизводимость не зависела от последующих правок справочника,  
  - JSON **breakdown** (топливо, ЗП, суточные, дороги по странам, промежуточные суммы, курсы НБУ, маржа),  
  - `distance_empty_km`, `distance_loaded_km`, `distance_total_km`,  
  - флаг `includes_dispatch_point0`.  
- Точка 0: либо поля в snapshot маршрута (`order=0`, тип `dispatch`), либо отдельная сущность, привязанная к расчёту (предпочтительно в **route snapshot**, чтобы совпадало с HERE-пересчётом).

## 8. API (черновик)

### 8.1 RBAC: сценарии расчёта
- Все endpoint-ы раздела **`/api/v1/admin/freight-scenarios`** (и при необходимости `/api/v1/admin/freight-scenarios/{id}`): **`hasAnyRole('ADMIN','MANAGER')`** для методов **GET** (список и по id), **POST** (создание), **PUT/PATCH** (изменение параметров), **DELETE** (или PATCH `isActive=false` — по выбранной политике проекта).
- Роль **`USER`**: нет доступа к CRUD сценариев и к админским endpoint расчёта; пользователь только отправляет заявку.
- Endpoint-ы расчёта по заявке (`country-breakdown`, `cost-preview`, создание quote по этому ТЗ): **`hasAnyRole('ADMIN','MANAGER')`** (согласовано с доступом к сценариям).

### 8.2 Маршруты endpoint-ов
- `GET /api/v1/admin/freight-scenarios` — список сценариев (опционально фильтр `activeOnly=true` для выпадающего списка в расчёте).  
- `GET /api/v1/admin/freight-scenarios/{id}` — один сценарий.  
- `POST /api/v1/admin/freight-scenarios` — создать сценарий.  
- `PUT` или `PATCH /api/v1/admin/freight-scenarios/{id}` — изменить параметры.  
- `DELETE /api/v1/admin/freight-scenarios/{id}` — удалить или деактивировать (согласовать с политикой ссылочной целостности на старые quote).  
- `GET /api/v1/admin/country-toll-rules` / CRUD.  
- `POST /api/v1/admin/route-requests/{id}/country-breakdown` — расчёт пробега по странам; **обязательные поля тела:** `scenarioId`, блок точки 0 (`dispatchPoint` **или** `dispatchPointOmitted: true`). Без них — `422` с кодом бизнес-ошибки.  
- `POST /api/v1/admin/route-requests/{id}/cost-preview` — полный preview себестоимости; те же предусловия, что и для breakdown (§3.1), иначе `422`.  
- `POST /api/v1/admin/route-requests/{id}/quotes` — расширить payload: `scenarioId`, `calculationDate`, точка 0 (или явный отказ), `seasonOverride?` → сервер **сначала** валидирует предусловия, затем считает пробег по странам и остальное; заполняет `totalAmount`, `currency`, breakdown.  
- `GET /api/v1/fx/nbu?date=` — внутренний/кэшируемый endpoint для фронта (опционально).

## 9. Frontend (Angular Material)
- В карточке заявки (**ADMIN/MANAGER**): блок «Расчёт» в порядке **§3.1**: сначала **точка 0** (или явно «нет»), затем **выбор сценария** из списка с сервера (`MatSelect` / autocomplete); кнопка «Рассчитать пробег по странам» / общий «Пересчитать» активна только когда оба заполнены; затем выбор **сезона** (override при необходимости), дата расчёта, таблица км по странам (MatTable), breakdown затрат, итог в валюте предложения.  
- Отдельный экран **«Сценарии расчёта»** (**ADMIN** и **MANAGER**): список сценариев, форма редактирования всех параметров из §5, создание/сохранение/деактивация — данные только через API §8.  
- Экран тарифов дорог по странам (по ролям, согласовать с §8 для `country-toll-rules`).

## 10. Критерии приемки
- [ ] **MANAGER** и **ADMIN** видят полный список заявок и детали (как минимум read; write — по согласованной матрице ролей).  
- [ ] Сценарии хранятся на сервере; **ADMIN** и **MANAGER** могут создавать/редактировать параметры сценариев и выбирать сценарий в расчёте по заявке; после сохранения quote в аудите виден снимок параметров на момент расчёта.  
- [ ] Пробег по странам **не** рассчитывается и **не** отображается как готовый результат, пока не заданы **точка 0** (или явный режим без неё) и **сценарий**; смена любого из них сбрасывает актуальность breakdown до нового расчёта.  
- [ ] Можно задать **точку 0** и увидеть увеличение порожнего пробега и влияние на топливо/суточные.  
- [ ] Выбор сценария меняет результат предсказуемо.  
- [ ] Расход гружёного топлива: при сезоне **не зима** используется **37** л/100 км, при **зиме** — **40** л/100 км (согласно §5.1 и `seasonMode`).  
- [ ] Дороги: для страны с тарифом «EUR/день» в расчёт попадает **2** дня.  
- [ ] Итоговая сумма quote конвертируется по **НБУ на дату расчёта**; в breakdown видны использованные курсы.  
- [ ] Повторный расчёт на ту же дату не дергает НБУ лишний раз (кэш).  
- [ ] Интеграционные тесты: мок НБУ, фиксированные длины → ожидаемые суммы.

## 11. Открытые вопросы к бизнесу
1. Зарплата **17% от фрахта** — точная база (от оборота с НДС/без, от чего вычитать сначала).  
2. `floor` vs `ceil` для `(L/600)`.  
3. Нужна ли **MANAGER** отправка quote клиенту или только просмотр/расчёт.  
4. Валюта суточных фиксирована в USD — конвертация по НБУ на дату расчёта?
